# 0.8 统一客户端预览

邻控使用同一套界面和本地客户端引擎。Windows 与 macOS 可以发起远程桌面，也可以在开启接收和批准后被控。Linux 候选版可以发起桌面和 SSH 连接，Linux 被控适配仍在开发。

## 安装与旧版兼容

Windows 解压后运行「打开邻控.cmd」；macOS 打开应用「邻控」。两端均自带运行环境。

Linux 有 Python 3.9 或更新版本时，运行 `python3 LinkoRemote-Linux.pyz` 即可安装到当前用户，并在应用菜单出现「邻控」。打开后使用默认浏览器显示邻控界面。SSH 还需要系统的 OpenSSH 客户端和桌面终端。Linux 候选必须连接支持 Linux 注册的新版中继。

预览版 Windows 配置位于 `%LOCALAPPDATA%\LinkoRemote`，macOS 配置位于 `~/Library/Application Support/LinkoRemote`，Linux 默认使用 `~/.config/linko-remote`，并支持 `XDG_CONFIG_HOME`。0.7 的安装与配对保留在原客户端中，尚未自动迁移到新协议。连接双方均需安装统一预览版。

## 建立连接

1. 在将要共享桌面的电脑开启允许连接，生成 10 分钟有效的 12 位连接码。可以复制完整连接码，也可以保存并发送 `.linko` 邀请文件。
2. 在另一台已安装邻控的电脑粘贴连接码，或选择「打开邀请文件」预填，再点「发起连接」。
3. 共享桌面的电脑核对申请者名称、设备号和系统，选择「允许本次连接」或「长期授权」。临时授权为一小时。
4. 发起电脑打开桌面，取得画面后操作。

两端能通过同一个预先配置的连接服务通信时，连接码可用于异地配对。完整码和邀请文件保留服务身份校验。连接码只能创建一次申请，授权由共享桌面的一方选择。反向操作需单独批准。长期授权持续有效，直到在设备列表撤销。邻控重启时可恢复已有长期授权的接收，手动暂停会保留。断网期间暂停会立即停止本机接收，连回中继后再同步。Mac 接收连接需要录屏和辅助功能权限。本机缺少这些权限时，仍可查看连接状态和主动连接其他电脑。

## 传输与操作边界

预览服务使用独立的 HTTPS 中继并校验证书指纹。桌面会话只允许取屏和键鼠，不授予原版限定文件作业能力。每个操作使用唯一编号；回执丢失时只查询原结果，不自动重发输入。到期且未交付的请求会结束，已交付的取屏和状态查询也会在到期后释放。已交付的键鼠输入结果不明时，请按原编号查询。连接服务暂时不可用时，设备列表会显示「状态待更新」。

连续桌面目前通过中继传输独立 JPEG，并与逐步取屏和确认操作并存。Mac 适配目前只处理主显示器。预览中继依赖测试主机和临时公网隧道。同一台控制电脑的界面一次打开一个连续会话，连接服务支持多个目标各自运行会话。SSH 使用系统 OpenSSH、现有主机配置和密钥，对端需要开启 SSH 服务及已有可达路径。SSH 流量当前经系统的网络路径传输。

## 异地、同网和新设备的下一步验收

| 场景 | 当前候选和验收范围 |
| --- | --- |
| Mac、Windows 互联 | 代码支持双向桌面和 SSH 启动入口。macOS 接收、不同实网和公共中继仍要单独验收。 |
| Linux 参与 | 发起桌面、已授权设备列表、系统 SSH 启动和用户菜单安装进入候选。新版中继接收 Linux 注册。Linux 已登录桌面的取屏和输入需继续接入桌面门户。 |
| 第一次发文件 | `.linko` 可在已装邻控的机器内预填共享方的连接申请。还要做邀请接收方主动共享的流程，以及安装完成后自动打开邀请界面的一体化引导。 |
| 局域网和异地 | 同一连接码继续负责定位和申请。下一步同网优先尝试经认证的直连，再测异地直连和中继兜底。配对与画面路线分别验收。 |
| 三台及以上 | 回环 TLS 测试覆盖同时连接两台和逐条撤销。独立网络、多窗口和失联切换另测。 |

长期服务需要一个固定、可自行维护的连接入口，承载设备信令和直连失败时的中继。先用独立测试环境验证，再决定服务器带宽和部署。正式做 SSH 穿透时沿用 OpenSSH 主机身份校验，并单独由目标机开启 SSH。桌面性能对照见[连续桌面复测](live-performance.md)。

同机直连试验使用隔离的 Python 3.12 和 aiortc 1.16.0。关闭 STUN 和 TURN 后，两端只交换 ICE host 候选，DTLS 建连成功，数据通道双向传输合成字节。下一轮把同一试验搬到两个局域网设备，并把握手身份与邻控的配对授权绑定，再测公网直连和中继回退。 [aiortc API](https://aiortc.readthedocs.io/en/latest/api.html) · [WebRTC 数据通道](https://webrtc.org/getting-started/data-channels)

## 0.8.1 更新检测与安装

设置页提供自动检查开关、手动检查、更新说明、下载进度和「安装并重启」。启动后约 8 秒自动检查，此后每 4 小时检查一次；检查与下载均在后台进行。安装只在用户选择后启动，有会话或未确认操作时阻止重启。

更新只读取本仓库的 GitHub Release，并按系统和架构选择安装包。HTTPS 重定向限定 GitHub 下载域名；SHA-256 必须与 GitHub 资产记录一致，安装前再次检查。ZIP 解压拒绝越界路径、符号链接、重名文件和超大内容。

Windows 按版本目录安装，保留上一版；macOS 在应用目录完成替换，并保留上一版应用包，替换失败恢复原包。新版启动后核对本地服务版本，失败时恢复或保留原启动入口。更新不会删除用户数据目录。Mac 被控权限仍需系统单独授权，更新程序不会自动开启。

旧 0.8.0 没有更新器，需手动安装本版一次。之后的版本可由软件内检测并更新。
