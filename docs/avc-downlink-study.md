# AVC 慢下行复测

基线是 `918911e`。此前仅下行的两次公网试验里，中继在开会话后 2744 / 2380 ms 收到首张 IDR，分别接收 200 / 219 帧。唯一一次媒体订阅在 4738 / 5354 ms 到达，此后发送端在 12804 / 13605 ms 读到租约失效，Canvas 无 AVC 绘制。详见[前次原始对照](../../viewer-startup-0703f5e/trials.md)。

## 交付路径

- 旧的 HTTP 媒体响应在约 3 秒内连续写 AVC，接收端读完分块响应才发下一次认证订阅。一次响应写入了多少媒体，与慢接收端何时读完是两个时点。旧路径也会在续订时按收到的序号承接参考帧。
- Viewer 和中继在 `live-open` 双方协商 `avc_view_batch=1`。协商后，每个响应最多选择 250 ms 内的媒体，媒体记录总量上限为 64 KiB，首条完整记录超过上限时独占一个响应，仍受原有单帧限制。Viewer 复用固定证书指纹的 TLS 连接，每次读完整个响应即重新订阅。
- 中继优先取 350 ms 内可连续解码的下一帧，断链时选同一时限内最新的 IDR。找不到可用参考时沿现有发送端信号请求 IDR。Viewer 在确认序号前按产品帧龄检查丢弃过期帧和无参考的 P 帧。单次响应读取限时 2.5 秒，媒体传输失败可重新订阅一次，新连接从 IDR 开始。JPEG 仍可走原降级路径。
- 只有通过身份与授权检查的订阅才刷新 Viewer 租约，实时写出媒体不会续租。发送端的 8 秒活跃期限、单次最多 2.5 秒的工作租约、Viewer 和中继的 1.5 秒画面新鲜度要求、键鼠编号和回执规则沿用原实现。任一侧缺少协商能力时使用原 AVC 批次，旧 JPEG 交付仍使用原入口。

## 方法

在同一台 Mac 上用独立临时配置启动两套真实中继和桌面引擎，执行真实 TLS 握手、证书校验和授权流程。Windows 发送端由实际 Python 代理配合合成 mailbox 喂入同一份预编码的 720p、20 fps、最长 20 帧 GOP 的 H.264 滚动内容。Viewer 使用离屏 WKWebView 的产品页面与 WebCodecs，记录实际 Canvas 绘制。接收端链路经过回环 TCP 字节代理，两方向各固定增加 300 ms，只有中继到 Viewer 的方向限速。上行、合成输入执行和时钟均在本机。窗口从发起打开会话计算，版本和试次顺序交替。

首帧和绘制率统计 H.264 Canvas，绘制率使用完整窗口。帧龄用合成采集至 Canvas 的同机时钟测量，帧间隔是相邻实际绘制的时间差。代理限制 TLS 字节的交付速率和传播时间。代理内核缓冲与线上拥塞窗口、丢包、抖动及跨连接带宽竞争不同。输入回执来自合成 mailbox，Windows 原生捕获、实际键鼠执行、显示器刷新和公网交互效果需要独立测量。

## 时序与结果

在 1.6 Mbps、实测约 608 ms RTT 下，基线三轮中继均只收到一次媒体订阅，仍接收 158、156、184 帧。首条 IDR 写入响应时已经 1171、1205、1189 ms 老，叠加请求往返及发送排队后超过现有 Viewer 新鲜度门槛。单个响应写出了 1.05–1.32 MB 媒体记录。三轮 AVC 均在 9.4–11.1 秒被关闭，Canvas 无 AVC 绘制。

候选首条 IDR 改为序号 21，中继写出时帧龄 182–204 ms。三轮各成功订阅 15 次，最大续订间隔 1.07 秒，发送端和 Viewer 在 17 秒窗口结束时仍走 AVC。三轮实绘 36、37、42 帧，合并实际帧龄 P50/P95 为 527/701 ms，合并绘制间隔 P50/P95 为 94/918 ms，最长单次间隔 1.81 秒。每轮发出 12 次补 IDR 请求。11 条被中继接受的合成输入都有唯一 mailbox 与 Viewer 回执，另有 2 次只记到本地排队。

短批次在高 RTT 时仍呈批内小间隔、批间长间隔。这里验证的是弱下行时及时取得更新画面并让续租继续，帧率和帧间隔仍不足以表现为 20 fps 连续视频。较大的单个访问单元仍需要足够带宽在新鲜度窗口内交付。较高 RTT 且带宽充足时的吞吐、自适应编码效果需另外测量。前次公网路径的具体丢包、带宽、转发缓冲和断开原因仍无法从本机代理反推。

不限速回环两轮中，两版均实际绘出约 19.6–19.7 fps，候选首绘 267 / 282 ms，基线首绘见逐轮数据。候选在同一条 TLS 连接上每轮发出 111 次订阅，基线每轮 5 次。回环画面率相近，候选提高了中继请求频率。多会话的 CPU、连接容量及请求处理开销未测。

在 1.0 Mbps、实测约 609 ms RTT 下，基线两轮分别在 2768 / 2974 ms 收到唯一一次订阅，在 10804 / 11194 ms 读到发送端租约失效，间隔 8.04 / 8.22 秒。中继接收 185 / 182 帧，Canvas 均无绘制。候选两轮各订阅 11 次，最大间隔 1.24 秒，14 秒窗口结束时均保持 H.264。合并实测帧龄 P50/P95 为 765/990 ms，绘制间隔 P50/P95 为 156/1120 ms。第一轮有 2 条合成输入完成回执，第二轮只有一条本地排队记录。探针一次只等待一条输入，待回执的本地排队若未提交，该轮会停止后续输入探测。

## 复跑与核验

沿用同级目录 `viewer-startup-0703f5e` 中的合成片源生成器、发送端 mailbox 和离屏 Viewer 探针。下行代理及两套版本的装载由 [downlink_tls.py](../tests/video_stream/downlink_tls.py) 执行。 [压缩原始记录](../tests/video_stream/downlink_local_results.json.gz) 包含源代码 SHA-256、逐帧采集与绘制时点、订阅时序、代理 RTT 探针和合成输入回执。

```sh
PYTHONDONTWRITEBYTECODE=1 uv run --offline --no-project --python 3.12 \
  --with-requirements tests/video_stream/requirements.txt python tests/video_stream/downlink_tls.py \
  --seconds 17 --repeats 3 --mbps 1.6 --modes slow --output /tmp/lanpilot-downlink-slow.json

PYTHONDONTWRITEBYTECODE=1 uv run --offline --no-project --python 3.12 \
  --with-requirements tests/video_stream/requirements.txt python tests/video_stream/downlink_tls.py \
  --seconds 14 --repeats 2 --mbps 1.0 --modes slow direct --output /tmp/lanpilot-downlink-control.json
```

68 项 Python 连续桌面测试和 3 项 JavaScript Viewer 测试通过。新增 TLS 回归覆盖缺少协商字段时兼容旧批次、过旧 IDR 触发补帧、按已确认序号续流、完整大帧独占批次，以及拒绝非 Viewer 订阅和撤销授权后续订。全部正式试次使用本机合成源和回环链路，未部署。
