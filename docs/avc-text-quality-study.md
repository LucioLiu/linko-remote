# H.264 14 px 文字同帧复核

基于 `859aa0e`。原研究的定时 OCR 样本里，64/68 张为 IDR，而实际绘制的 732 帧只有 195 张为 IDR。历史样本的零完整短语可以重现，反映的主要是续订批次开头的关键帧。软件解码已能复现主要像素损失。720p 低档在停滚时保留预测链，可以避免一次周期性 IDR 造成的文字重新模糊。

## 方法

- 用采集序号、GOP 起点和偏移重建历史样本，逐档核验有序访问单元的 SHA-256。历史 Canvas 裁剪 PNG 也单独核验哈希。由产品 JS 的 `decodeLiveAvc`、`drawLiveMedia` 和 `presentLiveFrame` 保证截图和帧序对应，下一帧等待当前 Canvas 和两张窗口快照完成。
- 四级比较用同一块物理桌面区域 `x=8..431, y=52..155`，包括源图、FFmpeg 软件解码、实际 WKWebView 的 Canvas 和应用 1220×860 点布局快照。像素比较在统一的 424×104 尺寸进行，报告 RGB 通道绝对误差。快照 OCR 保留各自输出分辨率下的区域尺寸。DPR 2 的 WKWebView 将快照宽度解释为点，实际输出像素用断言核验。1× 输出来自同一个 DPR 2 WKWebView 的缩小快照。
- Vision 固定美式英语并关闭语言自动检测和校正。真值从源场景的字体边界生成，裁剪边缘的半行不纳入。按坐标匹配列和行，避免 OCR 按列返回引起错序。字符错误率用编辑距离除以真值字符数，转大写并只保留 A–Z 和 0–9，漏行记为删除。同一张未编码源图用相同参数作为对照。
- 受控序列包括约一秒静止、约一秒每帧滚动 7 px、约一秒停滚。两次编码只改定期 GOP，分别在停滚首帧插入 IDR，以及保持这一段预测链连续。停滚取第 0、50、200、450 和 950 ms 的内容。静止阶段包含启动 IDR，滚动阶段从此前静止画面开始。历史序列则从连续密集滚动的多个位置开始编码，多次按需重启参考链，两者分别报告。

## 弱网回归

本机回环 TLS 限速，往返约 600 ms。定期 GOP 的对照固定低档参数及旧传输基线，并在 1.6 Mbps 下反转顺序复跑。有效帧率从连接开始计，帧龄从合成采集到 WKWebView 实际绘制。样本来自独立的 13 或 16 秒窗口，机器负载每轮有波动。

| 带宽及窗口 | 定期 GOP | 实绘 FPS | 帧龄 P95 | 帧间隔 P95 | 已提交回执 | IDR 请求 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 Mbps · 13 s | 2 秒 | 2.92 | 558 ms | 890 ms | 3/3 | 11 |
| 1 Mbps · 13 s | 3 秒 | 2.77 | 426 ms | 894 ms | 4/4 | 11 |
| 1.6 Mbps · 13 s | 2 秒 | 2.15 | 373 ms | 936 ms | 3/3 | 12 |
| 1.6 Mbps · 13 s | 3 秒 | 2.23 | 374 ms | 1695 ms | 3/3 | 13 |
| 1.6 Mbps · 16 s 复测 | 3 秒 | 2.31 | 378 ms | 1729 ms | 2/2 | 16 |
| 1.6 Mbps · 16 s 复测 | 2 秒 | 2.19 | 380 ms | 1689 ms | 6/6 | 16 |

两种周期的六轮都持续使用 H.264，已提交输入全部收到回执。1.6 Mbps 首轮的 3 秒组帧间隔 P95 为 1.70 秒，反向复测时两组都在 1.69–1.73 秒。六轮相邻采集关键帧最长相隔 28 帧，低于原来的 40 帧周期，弱链路频繁主动重同步。两种夹具有 1620 个起点和偏移相同的访问单元。其中 60 个差异全为同长度的 IDR SEI 信息，承载画面的 NAL 相同。这些回环结果用于确认重同步和输入，首轮帧间隔差异在反向复测中大幅收窄，Windows MFT 的实际出帧仍待验证。

175 kbit 缓冲也做了两轮每档对照。它在受控停滚首帧插入 IDR 时把低档 Canvas CER 从 65.2% 降到 57.9%，同序列 IDR 中位大小从 7084 增到 12133 字节。弱网滚动样本总计 0/402 条完整短语，采到的预测帧距最近 IDR 最多 10 帧。增大缓冲会增加关键帧开销，当前低档仍采用 100 kbit。

## 实现

编码发送端只把协商低档的定期 GOP 从 2 秒延到 3 秒。起播和中继主动请求的 IDR 路径照常走，低档仍是 720p 上限、20 fps、750 kbps 和 12,500 字节缓冲。MFT 如果拒绝延长 GOP，仍尝试原来的 2 秒设置。使用旧档或旧协议的双方继续使用原设置。长 GOP 主要减少定期刷新打断已经清晰的参考链，首张低预算 IDR 和链路丢失参考帧后的按需 IDR 仍会模糊。

本机上逐档复跑，30 项连续媒体 Python 测试和 3 项 Viewer JavaScript 测试通过。C++ 协议测试通过 ASan 和 UBSan。未部署。Windows x64 和 ARM64 使用交叉编译验证，Windows 原生 MFT 的画质、编码器设置接受情况及办公室链路仍待实机测量。

## 复跑

[压缩原始数据](../tests/video_stream/avc_text_quality_results.json.gz)包含历史 PNG 哈希、逐帧阶段和位置、像素差、Vision 输出、字符编辑数，以及所有弱网跑次。指定的输出目录还保存每张对照 ROI 的 PNG。

```sh
run_python() {
  uv run --offline --no-project --python 3.12 \
    --with-requirements tests/video_stream/requirements.txt python "$@"
}
run_python tests/video_stream/avc_quality.py --output /tmp/lanpilot-avc-quality
run_python tests/video_stream/downlink_tls.py --seconds 13 --repeats 2 \
  --rates 1 1.6 --modes slow --profiles small-idr vbv175 --output /tmp/lanpilot-avc-buffer.json
for gop in 40 60; do
  run_python tests/video_stream/downlink_tls.py --seconds 13 --repeats 1 \
    --rates 1 1.6 --modes slow --profiles small-idr --gop "$gop" \
    --output "/tmp/lanpilot-avc-gop-$gop.json"
done
for gop in 60 40; do
  run_python tests/video_stream/downlink_tls.py --seconds 16 --repeats 1 \
    --rates 1.6 --modes slow --profiles small-idr --gop "$gop" \
    --output "/tmp/lanpilot-avc-gop-$gop-repeat.json"
done
```
