# 邀请新的 Windows 电脑

Mac 邻控中选择 **添加电脑 → 生成邀请**，填写能区分设备的名称，保存 `LanPilot-Connect.cmd`。通过可信的私密渠道将整个文件发给目标 Windows 用户。对方双击后，会看到设备名和这台 Mac 能查看、操作其已登录桌面的说明；选择“是”即开始接入。安装器不需要管理员权限，也不用输入 IP、导出公钥、拷回 XML 或手工配置远程路由。Windows 的下载防护或公司策略可能另外提示或禁止脚本；邻控不会代替用户绕过它们。

每个文件只允许一台新 Windows 账户身份接入；默认 15 分钟失效。它含临时凭据，请勿上传到公开仓库、公开下载目录或群聊。过期时重新生成。已经配对的 Windows 不接受新身份邀请，不会覆盖原配对。Mac 面板刷新后**显示在线**说明轮询已到达；应再使用一次只读观察确认可用，不能只凭“安装完成”判断。

从 CLI 生成相同文件：

```sh
"$HOME/Applications/邻控.app/Contents/Resources/lanpilot" invite '杭州办公室' "$HOME/Downloads/LanPilot-Connect.cmd"
```

**控制端一次性准备。** 已经使用 bore 的 Mac 会自动复用其配置中的中继主机，并选择一个独立的公网端口；既有单设备隧道不变。邻控先对实际公网地址做 TLS 指纹校验，连不通不会生成邀请。新 Mac 需要安装邻控及启动后台 broker；要接入不同 Wi-Fi 的电脑，先在 `~/Library/Application Support/LanPilot/WAN/bin/bore` 放置自己的 bore 客户端，并用 `lanpilot invite-route --server 中继主机 --port 可用公网端口` 初次配置。公共中继的稳定性、开放端口和可用性不受邻控保证；固定的自有原始 TCP 中继更合适。只在同网使用时，`lanpilot invite-route --lan-only` 可免中继。不同辅助身份共用一个入口，网关根据独立设备凭据分流，不需要为每台电脑手工分配公网端口。

**身份与重试。** Windows 在本用户账户生成 RSA-2048 密钥，私钥使用 Windows DPAPI 保护。邀请通过 TLS 使用安装文件内的固定 SHA-256 证书指纹兑换；Mac 只保存邀请凭据的摘要。首次兑换锁定公钥；在有效期内，同一公钥丢包后重取相同加密回执，不创建第二台设备。不同公钥、已过期或不存在的邀请不被接受。每个设备独立持有 broker token、日志、管理口令和请求队列；新邀请的设备使用同一网关证书，Mac 信任边界内的运行目录共享该私钥。外部入口只接受兑换与设备轮询/回执，不提供提交操作或读管理结果的接口。

若需要在已经配对的 Windows 上**独立验收**，可用 CLI 增加 `--isolated-test`。此模式使用单独的临时目录、独立面板锁、强制只读，且不写开机启动和桌面快捷方式。它验证密钥、兑换、安装和远端真实屏幕，不代表新 Windows 用户的真实登录自启已验证。
