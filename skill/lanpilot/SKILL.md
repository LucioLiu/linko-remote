# 邻控

多台设备时，按用户点名的设备选择唯一 id；不把“另一台电脑”默认等同于固定设备。若有多个可用目标且用户未指明，先问目标。

先发现 `lanpilot` MCP 工具，用 `list_devices` 核对设备名和在线状态；用 `observe` 取得真实屏幕再操作。心跳在线不等于桌面可操作。

- `act` 必须使用刚刚观察该设备得到的 frame_id。看清目标再操作，逐步检查回执；前一步失败不得继续依赖动作。
- 成功动作的回执也包含新截图和 frame_id，可检查后直接用于下一步，省去重复 observe。点击不填 button 时默认左键。
- 输入会影响被控电脑当前桌面。用户正在使用被控端时停止输入；本机 Mac 无需打开远控窗口。
- 使用用户本轮任务已有授权。不要把设备已配对当成业务审批、提交或发送许可。
- 返回未确认或 input_attempted=true 后取图失败：只 `recover` 原请求并重新观察；不重放正文或点击。
- 断线先检查设备状态和邻控服务。不得自动打开 UU、切换本机前台、关闭目标保护或修改设备身份。
- 无 MCP 工具时，可后台执行已安装应用的 `Contents/Resources/lanpilot devices`。本机固定入口为 `~/Applications/邻控.app`，命令支持 status/observe/recover/action；不自行编写新的临时控制脚本。新连接器需客户端重新加载后才能出现在已有对话中。

多台 Windows 可以同时操作。按设备 ID 独立派发观察和动作，一台机器等待回执时可继续处理另一台。每台只使用自己的画面和 frame_id；同一设备保持动作顺序。Mac 已实测通过跨网中继同时向两台测试机输入不同内容，局域网亦可使用。新会话先重新核对设备当前状态。

Windows 锁屏、管理员安全桌面及高权限窗口需按当前桌面实际能力判断。此链路由 Mac 控制 Windows。
